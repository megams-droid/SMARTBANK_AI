# 14. EXPLAINABLE AI ENGINE
Create one reusable scoring engine shared by all security modules.
Architecture:
=== PAGE 11 ===
```text
Input Event
     ↓
Feature Extraction
     ↓
Signal Detection
     ↓
Weighted Risk Engine
     ↓
Risk Score
     ↓
Risk Classification
     ↓
Explanation Generator
     ↓
Recommended Action
```
Example formula:
```text
Risk Score =
Ʃ(signal weight × signal triggered)
```
Normalize to:
**0–100**
Every AI/security decision MUST explain:
1. What happened?
2. Why was it detected?
3. What evidence was considered?
4. What is the risk?
5. What should the user/admin do?
Do not call a rule engine a trained AI model.
If no real ML model is connected, label it:
**Explainable AI-assisted rule-based engine**

# 17. RANSOMWARE DETECTION
Create:
## Ransomware Sentinel
=== PAGE 14 ===
Because this is a banking application, implement ransomware detection as a 
**safe application/data-layer simulation** .
Monitor simulated indicators such as:
* Rapid file modifications
* Rapid record modifications
* Abnormal rename activity
* Suspicious extension changes
* Abnormal access bursts
* Decoy/honeypot access
Create safe decoy records/files.
When the simulation detects ransomware-like activity:
1. Generate alert.
2. Calculate risk score.
3. Identify affected asset.
4. Create incident timeline.
5. Recommend defensive action.
6. Notify admin/security analyst.
7. Record the incident.
Do NOT create actual ransomware.
Do NOT encrypt user files.
